502 / Origin / WAF Fast Triage

Start here before changing policy. One broken hop can masquerade as another.
1Public WAF URLResolve DNS, TLS handshake, headers, status, timings. Does the request reach the WAF edge?
2Origin directlyFrom an authorized network, pin Host/SNI to origin and test HTTP/TLS. This isolates origin health from WAF.
3Origin ACLConfirm only current tenant WAF SaaS source IPs can enter. A blocked SaaS proxy commonly surfaces as 502/504.
4Fog ≠ data pathFor agents/gateways, verify outbound HTTPS/443 to Fog separately. Fog health does not prove WAF SaaS→origin reachability.
Likely 502 families: origin TCP refusal/reset, wrong upstream port, origin TLS/SNI mismatch, untrusted/expired certificate, origin firewall/ACL rejecting the WAF SaaS proxy, DNS resolving the wrong origin, reverse-proxy upstream failure, or an application/backend returning 502 itself. Compare direct-origin and WAF-path results before blaming either side.
